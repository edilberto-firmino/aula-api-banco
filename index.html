API com Python e SQLite: nosso primeiro CRUD com banco de dados

Na primeira aula, construímos uma API de produtos com FastAPI e guardamos os cadastros em um dicionário. Hoje vamos manter as mesmas rotas, mas salvar os produtos em um banco de dados. Assim, eles continuarão disponíveis depois que o servidor for reiniciado.

Ao terminar, você conseguirá: criar uma tabela com um script pronto, conectar Python ao SQLite e cadastrar, consultar, atualizar e excluir produtos pela página /docs.

Este é um roteiro para construir o projeto durante a aula. Os arquivos e comandos abaixo devem ser criados e executados por você. Vamos usar um único main.py para a API, como na aula anterior, e dois arquivos de preparação do banco.

Revisar a primeira aula de API →

1. O que muda em relação — primeira aula?

Fluxo da aplicação
Navegador /docs → requisição HTTP → FastAPI → SQLite (loja.db)
Navegador /docs ← resposta JSON  ← FastAPI ← dados da tabela
Antes: memóriaAgora: banco de dados
Dicionário produtos = {}.Tabela produtos no arquivo loja.db.
Contador proximo_id criado no Python.ID gerado pelo SQLite.
Dados desaparecem ao reiniciar a API.Dados permanecem no arquivo do banco.
Acesso com chaves do dicionário.Acesso com comandos SQL.

Persistência significa manter os dados salvos depois que o programa termina. O SQLite é um banco que armazena seus dados em um arquivo e dispensa um servidor separado. Nesta aula, não precisamos instalar MySQL, cadastrar usuário nem configurar senha.

O banco é o arquivo loja.db. A tabela é a estrutura produtos dentro dele. Cada linha é um produto e cada coluna é um atributo: id, nome e preco.

2. Prepare a pasta e o ambiente virtual

Use Python 3.10 ou superior e o VS Code. Abra um terminal PowerShell. Crie uma pasta nova para o exercício, separada do projeto da aula anterior:

PowerShell — terminal
mkdir minha-api-banco
cd minha-api-banco
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install "fastapi[standard]"

Se você já abriu uma pasta vazia do exercício no VS Code, pule mkdir e cd. Se python não funcionar, tente py para criar o ambiente. O ambiente virtual separa os pacotes deste projeto dos demais.

Se a ativação for bloqueada, use diretamente o Python do ambiente para instalar:

PowerShell — alternativa sem ativação
.\.venv\Scripts\python.exe -m pip install "fastapi[standard]"

No Linux/macOS, crie o ambiente com python3 -m venv .venv, ative com source .venv/bin/activate e execute a instalação com python -m pip install "fastapi[standard]".

Confira se o SQLite está disponível no seu Python:

Terminal
python -c "import sqlite3; print(sqlite3.sqlite_version)"

Deve aparecer um número de versão. O módulo sqlite3 já acompanha as instalações usuais do Python; não execute pip install sqlite3.

4. Crie a tabela com o script pronto

Crie schema.sql no VS Code e copie o script abaixo. Ele está pronto para que possamos dedicar a maior parte da aula ao código Python:

schema.sql ← script SQLite
CREATE TABLE IF NOT EXISTS produtos (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    nome TEXT NOT NULL CHECK (length(trim(nome)) > 0),
    preco REAL NOT NULL CHECK (preco > 0)
);
TrechoSignificado
CREATE TABLE IF NOT EXISTSCria a tabela se ela ainda não existir. Executar novamente não apaga os produtos.
id INTEGER PRIMARY KEY AUTOINCREMENTIdentificador inteiro, único e gerado pelo banco. Não precisamos de um contador global.
nome TEXT NOT NULLNome em texto, obrigatório. O CHECK impede nome vazio ou composto apenas de espaços comuns.
preco REAL NOT NULL CHECK (preco > 0)Preço numérico obrigatório e maior que zero.

O ponto e vírgula encerra o comando SQL. Não precisamos escrever CREATE DATABASE: o SQLite cria o arquivo quando o Python abre a conexão.

Execute o SQL pelo Python

Crie preparar_banco.py e copie:

preparar_banco.py — Python
import sqlite3
from pathlib import Path

PASTA = Path(__file__).resolve().parent
caminho_banco = PASTA / "loja.db"
sql = (PASTA / "schema.sql").read_text(encoding="utf-8")

conexao = sqlite3.connect(caminho_banco)
try:
    conexao.executescript(sql)
    conexao.commit()
finally:
    conexao.close()

print(f"Banco e tabela prontos em: {caminho_banco}")

Salve os dois arquivos. No terminal da pasta do exercício, execute:

Terminal
python preparar_banco.py

Sem ativação, use .\.venv\Scripts\python.exe preparar_banco.py. A mensagem deve informar o caminho de loja.db, que aparecerá na pasta. Não tente editar esse arquivo como texto.

  • Path(__file__).resolve().parent encontra a pasta do próprio script. Assim, o banco fica sempre junto dos arquivos do projeto.
  • read_text() lê o arquivo SQL; executescript() executa seu conteúdo.
  • commit() confirma alterações; close() encerra a conexão. O bloco finally garante o fechamento mesmo se ocorrer um erro.

Confira antes de continuar: o comando terminou sem erro e o arquivo loja.db apareceu? Execute o preparador novamente: ele deve funcionar sem apagar os registros. Atenção: IF NOT EXISTS não altera uma tabela que já existe; mudanças de estrutura exigem outro comando SQL.

5. Faça a primeira conexão da API com o banco

Crie main.py e escreva esta primeira versão. A função conectar() abre uma conexão nova cada vez que precisamos consultar o banco:

main.py — primeira versão
import sqlite3
from pathlib import Path
from fastapi import FastAPI

app = FastAPI(title="API de Produtos com SQLite")
CAMINHO_BANCO = Path(__file__).resolve().parent / "loja.db"


def conectar():
    conexao = sqlite3.connect(CAMINHO_BANCO)
    conexao.row_factory = sqlite3.Row
    return conexao


@app.get("/produtos")
def listar_produtos():
    conexao = conectar()
    try:
        linhas = conexao.execute(
            "SELECT id, nome, preco FROM produtos ORDER BY id"
        ).fetchall()
        return [dict(linha) for linha in linhas]
    finally:
        conexao.close()
Terminal — iniciar o servidor
fastapi dev main.py

Sem ativação, use .\.venv\Scripts\fastapi.exe dev main.py. Abra http://127.0.0.1:8000/docs. Em GET /produtos, clique em Try it out → Execute. Em um banco novo, o resultado esperado é status 200 e [].

O SELECT lê as linhas da tabela; fetchall() busca todos os resultados. sqlite3.Row permite acessar colunas pelo nome, e dict(linha) converte cada resultado em um dicionário que o FastAPI devolve como JSON. ORDER BY id organiza a lista pelo ID.

Deixe o terminal do servidor aberto. Para pará-lo, use Ctrl + C. O servidor pode recarregar ao salvar o código; agora os produtos continuam no banco.

6. Entenda o CRUD e sua relação com SQL

OperaçãoMétodo e rotaSQLSucesso

O método HTTP descreve o pedido do cliente. O comando SQL realiza a operação no banco. A API faz a ligação entre os dois. O navegador na barra de endereços envia GET; para POST, PUT e DELETE, vamos continuar usando o /docs.

7. Monte o código completo do CRUD

Substitua todo o conteúdo de main.py pelo código abaixo. Não acrescente este bloco ao anterior, pois isso duplicaria funções e rotas. O SQL e o preparador continuam como estão.

main.py — código completo
import sqlite3
from pathlib import Path

from fastapi import FastAPI, HTTPException
from pydantic import BaseModel, Field, field_validator

app = FastAPI(title="API de Produtos com SQLite")
CAMINHO_BANCO = Path(__file__).resolve().parent / "loja.db"


class ProdutoEntrada(BaseModel):
    nome: str = Field(min_length=1)
    preco: float = Field(gt=0, allow_inf_nan=False)

    @field_validator("nome")
    @classmethod
    def validar_nome(cls, valor):
        valor = valor.strip()
        if not valor:
            raise ValueError("O nome não pode conter apenas espaços")
        return valor


def conectar():
    conexao = sqlite3.connect(CAMINHO_BANCO)
    conexao.row_factory = sqlite3.Row
    return conexao


@app.get("/")
def inicio():
    return {"mensagem": "API de produtos com SQLite funcionando!"}


@app.get("/produtos")
def listar_produtos():
    conexao = conectar()
    try:
        linhas = conexao.execute(
            "SELECT id, nome, preco FROM produtos ORDER BY id"
        ).fetchall()
        return [dict(linha) for linha in linhas]
    finally:
        conexao.close()


@app.get("/produtos/{produto_id}")
def buscar_produto(produto_id: int):
    conexao = conectar()
    try:
        linha = conexao.execute(
            "SELECT id, nome, preco FROM produtos WHERE id = ?",
            (produto_id,),
        ).fetchone()
        if linha is None:
            raise HTTPException(status_code=404, detail="Produto não encontrado")
        return dict(linha)
    finally:
        conexao.close()


@app.post("/produtos", status_code=201)
def criar_produto(produto: ProdutoEntrada):
    conexao = conectar()
    try:
        cursor = conexao.execute(
            "INSERT INTO produtos (nome, preco) VALUES (?, ?)",
            (produto.nome, produto.preco),
        )
        conexao.commit()
        return {"id": cursor.lastrowid, "nome": produto.nome, "preco": produto.preco}
    finally:
        conexao.close()


@app.put("/produtos/{produto_id}")
def atualizar_produto(produto_id: int, produto: ProdutoEntrada):
    conexao = conectar()
    try:
        cursor = conexao.execute(
            "UPDATE produtos SET nome = ?, preco = ? WHERE id = ?",
            (produto.nome, produto.preco, produto_id),
        )
        if cursor.rowcount == 0:
            raise HTTPException(status_code=404, detail="Produto não encontrado")
        conexao.commit()
        return {"id": produto_id, "nome": produto.nome, "preco": produto.preco}
    finally:
        conexao.close()


@app.delete("/produtos/{produto_id}")
def excluir_produto(produto_id: int):
    conexao = conectar()
    try:
        cursor = conexao.execute(
            "DELETE FROM produtos WHERE id = ?", (produto_id,)
        )
        if cursor.rowcount == 0:
            raise HTTPException(status_code=404, detail="Produto não encontrado")
        conexao.commit()
        return {"mensagem": "Produto excluído com sucesso"}
    finally:
        conexao.close()

Salve, aguarde o recarregamento e atualize o /docs. Se o servidor estiver parado, execute fastapi dev main.py. Você verá as seis operações, incluindo a mensagem inicial em GET /.

8. Entenda as partes novas do código

Classes e orientação a objetos

ProdutoEntrada é uma classe que herda de BaseModel. Essa é a herança que estudamos em POO: nossa classe aproveita a validação oferecida pela classe do Pydantic. nome e preco representam os dados esperados.

Quando uma requisição chega, o FastAPI valida o JSON e entrega um objeto em produto. Usamos produto.nome e produto.preco para acessar seus atributos. Essa classe descreve a entrada da API; ela não cria a tabela nem salva dados sozinha.

Field(gt=0) exige preço positivo; allow_inf_nan=False impede valores não finitos. O método validar_nome remove espaços nas extremidades com strip() e rejeita um nome composto apenas de espaços. @classmethod recebe a classe em cls; @field_validator registra esse método como validador do campo.

Conexão, consulta e gravação

TrechoO que faz
conectar()Abre uma conexão para a operação atual. A conexão não é compartilhada entre requisições.
execute(sql, parametros)Executa um comando SQL com os valores enviados separadamente.
fetchone()Obtém uma linha; devolve None se não encontrar.
fetchall()Obtém todas as linhas da consulta.
cursor.lastrowidObtém o ID gerado pelo INSERT.
cursor.rowcountInforma quantas linhas o UPDATE ou DELETE atingiu. Zero indica ID inexistente.
commit()Confirma INSERT, UPDATE e DELETE no arquivo do banco.
finally: conexao.close()Fecha a conexão tanto no sucesso quanto no erro. Alterações não confirmadas são desfeitas ao fechar.

Por que usamos interrogações no SQL?

Exemplo de consulta parametrizada
conexao.execute(
    "SELECT id, nome, preco FROM produtos WHERE id = ?",
    (produto_id,),
)

O ? marca o lugar de um valor. O SQLite recebe o valor separadamente e o trata como dado. Isso evita misturar dados com instruções SQL. Não monte consultas usando f-strings ou concatenando textos recebidos do usuário.

A vírgula em (produto_id,) cria uma tupla com um único elemento. No UPDATE, a ordem dos valores deve acompanhar a ordem dos pontos de interrogação: nome, preço e ID.

Observe o WHERE: ele limita atualização e exclusão ao ID informado. Sem WHERE id = ?, um UPDATE ou DELETE poderia atingir todos os produtos.

Usamos float e REAL para manter a continuidade da primeira aula. Eles podem produzir aproximações em valores decimais. Para cálculos financeiros, uma evolução é armazenar centavos inteiros e tratar os valores com regras monetárias adequadas.

9. Teste o CRUD passo a passo

Abra http://127.0.0.1:8000/docs. Em cada operação, use Try it out, preencha os campos e clique em Execute. Observe Server response, que mostra a resposta realmente recebida, e não somente a lista de respostas documentadas.

A. Liste antes de cadastrar

Execute GET /produtos. Em um banco novo, espere 200 e []. Se já houver produtos de testes anteriores, eles aparecerão: agora o armazenamento é persistente.

B. Cadastre um produto

Em POST /produtos, substitua o Request body por:

JSON — corpo do POST
{
  "nome": "Teclado",
  "preco": 120.0
}

Espere status 201. Se este for o primeiro cadastro no banco novo, a resposta será:

JSON — resposta esperada
{
  "id": 1,
  "nome": "Teclado",
  "preco": 120.0
}

Anote o ID realmente retornado. Não envie ID no cadastro. Ele pode ser diferente de 1 se você já fez outros testes. A exclusão de um produto não reinicia a numeração.

C. Liste e busque pelo ID

Execute GET /produtos: o produto deve aparecer na lista. Depois execute GET /produtos/{produto_id}, preenchendo o ID anotado. Espere 200 e os dados do produto.

D. Atualize nome e preço

Em PUT /produtos/{produto_id}, informe o mesmo ID e envie:

JSON — corpo do PUT
{
  "nome": "Teclado USB",
  "preco": 99.9
}

Espere 200 e o mesmo ID com os novos valores. Consulte novamente pelo GET para confirmar que a alteração foi salva. Nesta API, PUT exige os dois campos; não é uma atualização parcial.

E. Comprove que os dados permanecem salvos

Antes de excluir: pare o servidor com Ctrl + C e inicie novamente com fastapi dev main.py. Atualize o /docs e liste os produtos. O Teclado USB deve continuar cadastrado com o preço atualizado. Esse é o principal avanço em relação à aula anterior.

F. Exclua o produto

Execute DELETE /produtos/{produto_id} usando o ID anotado. Espere 200 e:

JSON — exclusão
{
  "mensagem": "Produto excluído com sucesso"
}

Busque novamente esse ID. Agora, espere 404 e:

JSON — produto inexistente
{
  "detail": "Produto não encontrado"
}

Execute DELETE novamente com o mesmo ID: também deve retornar 404. Liste os produtos: o item excluído não deve aparecer.

10. Teste os erros e as validações

JSON — preço inválido
{
  "nome": "Mouse",
  "preco": -10
}

Envie esse JSON pelo POST. Espere 422; o produto não deve ser cadastrado. Repita com preço zero, nome vazio, nome contendo apenas espaços e ausência do campo nome. Em JSON, use aspas duplas e ponto decimal: 99.9, nunca 99,9.

TesteResultado esperado
Preço negativo ou zero; nome vazio ou só espaços; campo obrigatório ausente.422 — validação da entrada.
GET, PUT ou DELETE com um ID que não existe, usando corpo válido no PUT.404 — produto não encontrado.
ID textual, como /produtos/abc.422 — o ID precisa ser inteiro.
Cadastro válido.201 ← criado.
Consulta, atualização ou exclusão válida.200 — sucesso.

Os erros 422 acontecem antes de executar o SQL. O 404 é produzido pelo nosso código quando a operação não encontra o produto. Se aparecer 500, confira a mensagem de erro no terminal do servidor; não é uma resposta esperada para os testes acima.

11. Atividade prática

  1. Crie os arquivos seguindo as etapas e prepare a tabela com o script fornecido.
  2. Cadastre três produtos e anote seus IDs.
  3. Liste os produtos e consulte um deles pelo ID.
  4. Atualize nome e preço de um produto e confirme com GET.
  5. Reinicie o servidor e comprove que os dados continuam salvos.
  6. Exclua um produto e confirme o 404 ao consultar seu ID.
  7. Envie preço negativo e nome composto apenas de espaços; registre o 422.
  8. Execute novamente preparar_banco.py e verifique que os produtos restantes continuam cadastrados.

Registre os resultados: anote método, rota, status e resposta de cada teste. Entregue os arquivos que você criou (main.py, preparar_banco.py e schema.sql) e as anotações, conforme orientação do professor. Não envie a pasta .venv.

Para discutir: por que os produtos não desaparecem mais? Quem gera o ID? Qual a diferença entre a classe ProdutoEntrada e a tabela produtos? O que aconteceria se esquecêssemos commit()? Por que precisamos de WHERE e dos parâmetros SQL?

Desafio opcional: adicione estoque inteiro e maior ou igual a zero. Planeje as mudanças no modelo, na tabela e nos comandos INSERT, SELECT e UPDATE. Para uma tabela existente, use ALTER TABLE produtos ADD COLUMN estoque INTEGER NOT NULL DEFAULT 0 CHECK (estoque >= 0); uma única vez. Apenas editar o CREATE TABLE e executar o preparador de novo não adicionará a coluna. Teste estoque zero e negativo.

12. Como retomar o projeto em outra aula

Abra a pasta do exercício no VS Code. No terminal PowerShell, execute:

PowerShell
.\.venv\Scripts\Activate.ps1
fastapi dev main.py

Sem ativação: .\.venv\Scripts\fastapi.exe dev main.py. Abra novamente http://127.0.0.1:8000/docs. Não é necessário reinstalar os pacotes nem preparar novamente a tabela enquanto o ambiente e o banco existirem.

Mantenha o arquivo loja.db para preservar os produtos. Ao mover o exercício para outro computador, copie os arquivos do projeto e o banco se quiser manter os cadastros; recrie o ambiente virtual no novo computador. Se o banco não existir, execute o preparador para criar uma tabela vazia.
